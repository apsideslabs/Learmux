
```
; <<>> DiG 9.18.28 <<>> example.com A
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41022
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0

;; QUESTION SECTION:
;example.com.                    IN      A

;; ANSWER SECTION:
example.com.            3600    IN      A       93.184.216.34

;; SERVER: 192.168.1.1#53(192.168.1.1)
```

The QUESTION SECTION repeats what you asked. The ANSWER SECTION holds the reply: the name, the number 3600, the record type, and the address. The 3600 is the time to live in seconds, the length of time a resolver may keep this answer before asking again.

For the IPv6 address, ask for the AAAA record:

```
dig +short example.com AAAA
```

```
2606:2800:220:1:248:1893:25c8:1946
```

The +short option prints only the answer, which is useful when you want the value and not the full report.

## Step 3: Names, addresses and CNAMEs

A name and an address are two different things. example.com is a name, and 93.184.216.34 is the address that name points to right now. The name stays the same even when the address changes, which is the whole point of DNS.
