Every page load and every API call is one HTTP request going out and one response coming back. Almost every bug in this track lives in the parts of that request the client controls, so first you have to see the request. In this lesson you will write a server that prints the raw bytes it receives, then a small file server, and find the first flaw in it: the path in the request line is used as a file path with no check.

<Callout type="warning" title="Only attack your own server">
Every example in this track runs on `127.0.0.1`, the loopback address that only reaches your own phone. You write the server, you start it, and you attack it. Never point these commands at a system you do not own or do not have written permission to test. Doing so is against the terms of most services and is a criminal offence in many countries.
</Callout>

## What you'll be able to do

- See the exact text of an HTTP request with a small socket server.
- Read a request line, its headers and its body.
- Run a server on `127.0.0.1` and talk to it with `curl`.
- Exploit a path that escapes the web root, then close it.

## Step 1: See the request as bytes

A request is just text sent over a socket. This server accepts one connection and prints whatever arrives. Write it as `rawview.py`.

```python
# rawview.py: show the exact bytes of an HTTP request
import socket

HOST, PORT = "127.0.0.1", 8000

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
server.bind((HOST, PORT))
server.listen(1)
print("listening on", HOST, PORT)

conn, addr = server.accept()
data = conn.recv(4096)
print("--- raw request from", addr[0], "---")
print(data.decode("utf-8", "replace"))

body = b"hello from the server\n"
conn.sendall(
    b"HTTP/1.1 200 OK\r\n"
    b"Content-Type: text/plain\r\n"
    b"Content-Length: " + str(len(body)).encode() + b"\r\n"
    b"\r\n" + body
)
conn.close()
server.close()
```

Run it in one Termux session.
