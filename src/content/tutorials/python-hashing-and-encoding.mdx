Python is strict about one thing most languages let you be vague about: the difference between text and bytes. A `str` is characters. A `bytes` is raw values. Hashing and encoding both work on bytes, so `encode()` is the doorway you have to walk through, and every program below walks through it.

## What you'll be able to do

- Explain why `len("café")` and `len("café".encode())` are different numbers.
- Round-trip bytes through hex and back.
- Take a SHA-256 digest and read its length.
- Encode to base64 and decode it again.
- Write a small function that uses all of it.

## Step 1: Characters and bytes are different things

Count the characters in `café`, then count the bytes.

<PyBlanks
  title="Characters and bytes"
  scaffold={`text = "café"
raw = @1

print("characters", @2)
print("bytes", len(raw))`}
  pieces={['len(text)', 'text.encode()', 'text']}
  answers={[1, 0]}
  expect={`characters 4
bytes 5`}
  hint="One gap turns text into bytes. The other counts the characters."
/>

Four characters, five bytes. The `é` is one character but it takes two bytes in UTF-8. That gap is the whole reason the distinction exists: the byte length depends on the encoding, the character length does not.

## Step 2: Round-trip through hex

Hex is how you look at bytes, because each byte is exactly two hex digits. This program goes to hex and back again.

<PyBlanks
  title="Bytes to hex and back"
  scaffold={`message = "Hi"
raw = message.encode()

as_hex = @1
back = bytes.fromhex(@2)

print(as_hex)
print(@3)`}
  pieces={['as_hex', 'raw.hex()', 'back', 'raw']}
  answers={[1, 0, 2]}
  expect={`4869
b'Hi'`}
  hint="One gap turns bytes into hex digits. The other two use the values already made."
/>

Eight lines, and it comes back to where it started, which is what "round trip" means. `H` is `48` and `i` is `69`. `bytes.fromhex` takes the hex back to bytes, and the print shows the `b` because it is still bytes, not text.

Every checksum you have ever seen is this: bytes written out as hex so you can read and compare them.

## Step 3: A digest, and how long it is

A hash function takes any amount of data and gives back a fixed number of bytes. SHA-256 always gives 32, whatever went in.

<PyBlanks
  title="A SHA-256 digest"
  scaffold={`import hashlib

message = b"hello termux"
digest = hashlib.@1(message)
as_hex = @2

print(len(as_hex))
print(@3)`}
  pieces={['as_hex[:8]', 'sha256', 'digest.hexdigest()', 'sha1']}
  answers={[1, 2, 0]}
  expect={`64
ba522390`}
  hint="The function name carries the bit size. Then turn the digest into hex, then take its first eight."
/>

Eight lines, two values, one printed figure of 64. That is 32 bytes written as two hex characters each. `sha1` would give 40 and `md5` would give 32, which is how you recognise a digest on sight: by its length.

`as_hex[:8]` is the first eight characters, which is the usual way to show a digest on a screen.

## Step 4: Base64, both ways

Base64 turns bytes into text using 64 safe characters, so binary can travel through anything that only carries text.

<PyBlanks
  title="Encode and decode base64"
  scaffold={`import base64

raw = b"hello termux"
encoded = base64.@1(raw)
decoded = base64.@2(encoded)

print(encoded)
print(@3)`}
  pieces={['b64decode', 'decoded', 'b64encode', 'raw']}
  answers={[2, 0, 1]}
  expect={`b'aGVsbG8gdGVybXV4'
b'hello termux'`}
  hint="One gap encodes, one decodes, and one prints a value already made."
/>

Eight lines, and the second print is the original message back again. Both are bytes, which is why both print with a `b`. Add `.decode()` if you need a string to put in a JSON field.

## Step 5: Why base64url exists

Standard base64 uses `+` and `/`. Both mean something in a URL, so a second alphabet swaps them for `-` and `_`.

<PyBlanks
  title="Two alphabets"
  scaffold={`import base64

raw = bytes([255, 255, 255])
standard = @1
url_safe = @2

print(standard)
print(url_safe)`}
  pieces={['base64.urlsafe_b64encode(raw)', 'base64.b64encode(raw)', 'base64.b64decode(raw)']}
  answers={[1, 0]}
  expect={`b'////'
b'____'`}
  hint="Same three bytes, two alphabets. The safe one is the one with url in the name."
/>

The same three bytes of 255 give `////` in the standard alphabet and `____` in the URL-safe one. This is exactly what a JWT uses, which is why a token never contains a `+` or a `/`.

## Step 6: A small tool that uses all of it

Now a function, called in a loop. This is the shape of a real script rather than a demonstration.

<PyBlanks
  title="A short-hash function"
  scaffold={`import hashlib

def short_hash(text):
    raw = @1
    digest = hashlib.sha256(raw).hexdigest()
    return @2

for word in ["alpha", "bravo"]:
    print(word, @3)`}
  pieces={['text.encode()', 'short_hash(word)', 'digest[:8]', 'text']}
  answers={[0, 2, 1]}
  expect={`alpha 8ed3f6ad
bravo f144a690`}
  hint="Encode the text, slice the digest, then call the function inside the loop."
/>

Ten lines. The function does the work once, and the loop calls it for each word. Two different words give two different digests, and each is eight characters because of the slice.

This is the part that makes a function worth writing: change the slice to `digest[:12]` and every call changes with it.

## Quick reference

| Piece | What it does |
| --- | --- |
| `"text".encode()` | text to bytes |
| `b"text"` | a bytes literal |
| `raw.hex()` | bytes as hex digits |
| `bytes.fromhex(s)` | hex back to bytes |
| `hashlib.sha256(...)` | a digest, which needs bytes |
| `.hexdigest()` | 64 hex characters for SHA-256 |
| `base64.b64encode(...)` | bytes to base64 text |
| `base64.b64decode(...)` | base64 text back to bytes |
| `base64.urlsafe_b64encode(...)` | the alphabet a URL or JWT can carry |
| `digest[:8]` | a short digest for a screen |
| `TypeError: Strings must be encoded` | you hashed text instead of bytes |
