Python is strict about one thing that most languages let you be vague about: the difference between text and bytes. A `str` is characters. A `bytes` is raw values. Hashing and encoding both work on bytes, so `encode()` is the doorway you have to walk through.

Every box below starts with the pieces placed for you. Turn that off once the shapes are familiar.

## What you'll be able to do

- Explain why `len("café")` and `len("café".encode())` are different.
- Take a SHA-256 digest and read it as hex.
- Encode to base64 and back, and know why base64url exists.
- Recognise the error you get when you hash text by mistake.

## Step 1: Text and bytes are different things

Count the characters in `café`, then count the bytes.

<PyBlanks
  title="Characters and bytes"
  scaffold={`text = "café"
print(len(text), len(text.@1()))`}
  pieces={['upper', 'decode', 'encode']}
  answers={[2]}
  expect="4 5"
  hint="One of those turns text into bytes. The other two go the wrong way or change nothing useful."
/>

Four characters, five bytes. The `é` is one character but it takes two bytes in UTF-8. That gap is the whole reason the distinction exists: bytes have a length that depends on the encoding, characters do not.

## Step 2: Bytes shown as hex

Hex is the usual way to look at bytes, because every byte is exactly two hex digits.

<PyBlanks
  title="Bytes as hex"
  scaffold={`print("Hi".encode().@1())`}
  pieces={['decode', 'hex', 'upper']}
  answers={[1]}
  expect="4869"
  hint="Which one turns bytes into their hex digits?"
/>

`H` is `48` and `i` is `69`. Two characters, four hex digits, no guessing. This is why every checksum you have ever seen is a long string of hex: it is bytes written out in a form you can read and compare.

## Step 3: A digest

A hash function takes any amount of data and gives back a fixed number of bytes. SHA-256 always gives 32 bytes, no matter whether the input was one character or a gigabyte.

<PyBlanks
  title="SHA-256"
  scaffold={`import hashlib

digest = hashlib.sha256(@1).hexdigest()
print(digest[:8])`}
  pieces={['"hello termux"', 'b"hello termux"', 'hello termux']}
  answers={[1]}
  expect="ba522390"
  hint="Two of those are not bytes. One of them is not even a value."/>

The `b` before the quote is what makes it bytes. `hashlib.sha256("hello termux")` raises `TypeError: Strings must be encoded before hashing`, and that error is a good friend: it tells you exactly what you forgot. `hexdigest()` then writes the 32 bytes out as 64 hex characters.

## Step 4: Base64

Base64 turns bytes into text using 64 safe characters, so binary can travel through anything that only carries text: a JSON field, an email header, a URL parameter.

<PyBlanks
  title="Base64"
  scaffold={`import base64

print(base64.b64encode(@1))`}
  pieces={['"hello termux"', 'b"hello termux"']}
  answers={[1]}
  expect="b'aGVsbG8gdGVybXV4'"
  hint="Same lesson as the hash: this works on bytes."/>

The result is still bytes, which is why it prints with a `b` in front. Add `.decode()` to get a string you can put in a JSON field.

## Step 5: Why base64url exists

Standard base64 uses `+` and `/`. Both mean something in a URL, so a second alphabet swaps them for `-` and `_`.

<PyBlanks
  title="Base64url"
  scaffold={`import base64

print(base64.@1(bytes([255, 255, 255])))`}
  pieces={['b64encode', 'b64decode', 'urlsafe_b64encode']}
  answers={[2]}
  expect="b'____'"
  hint="Three bytes of 255 come out as three slashes in the ordinary alphabet."
/>

The same three bytes give `////` in standard base64 and `____` in the URL-safe alphabet. This is exactly what a JWT uses, which is why a token never contains a `+` or a `/`.

## Step 6: A digest is always the same length

Whatever goes in, the length coming out is fixed. That is what makes a digest useful for comparison.

<PyBlanks
  title="Always 64"
  scaffold={`import hashlib

print(len(hashlib.@1(b"hello termux").hexdigest()))`}
  pieces={['sha1', 'sha256', 'md5']}
  answers={[1]}
  expect="64"
  hint="The one with 256 in its name gives 32 bytes, and hex writes each byte as two characters."
/>

64 characters for SHA-256. `md5` would give 32 and `sha1` would give 40, which is the point: the algorithm decides the length, and the length is how you recognise a digest on sight. Since it is fixed you can compare two of them without caring how big the files were.

## Quick reference

| Piece | What it does |
| --- | --- |
| `"text".encode()` | text to bytes |
| `b"text"` | a bytes literal |
| `.hex()` | bytes as hex digits |
| `hashlib.sha256(...)` | a digest, which needs bytes |
| `.hexdigest()` | the digest as 64 hex characters |
| `base64.b64encode(...)` | bytes to base64 text |
| `base64.urlsafe_b64encode(...)` | the alphabet a URL or JWT can carry |
| `.decode()` | bytes back to text |
| `TypeError: Strings must be encoded` | you hashed text instead of bytes |
