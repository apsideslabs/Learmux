You will build a password generator that runs at the Termux prompt, using only what is already on your phone. By the end you can make a random password of any length, work out how many bits of entropy it carries, and explain why some quick one-liners are worse than they look. This lesson builds the same generator as the interactive password generator in the Utilities section, so you can make the same passwords by hand without the tool.

If you would rather click than type, that tool lives at [the password generator](/utilities/password-generator/). Everything below does the same work in the shell.

## What you'll be able to do

- Explain why `$RANDOM` is not a source of secrets.
- Read random bytes from the system, and say what is subtly wrong with the usual `tr` pipeline.
- Generate a password with `openssl rand`, and another with Python's `secrets` module.
- Work out the entropy of a password with `awk` or Python.
- Explain why a loop that asks you to type the characters is the weakest option of all.

## Step 1: Why $RANDOM is not good enough

`$RANDOM` is a shell variable that hands you a number each time you read it. It is tempting because it needs no package at all.

```bash
echo $RANDOM
```

```text
19841
```

It gives a whole number from 0 to 32767. That range is only fifteen bits wide, because 2 to the power of 15 is 32768. Now watch what happens when you set the seed yourself.

```bash
RANDOM=42; echo $RANDOM; RANDOM=42; echo $RANDOM
```

```text
17772
17772
```

The two lines are identical. Setting `RANDOM` to a value reseeds it, and the same seed always produces the same sequence. That is the real problem: `$RANDOM` is not drawn from the device's randomness, it is computed from a small seed, so anyone who guesses the seed can replay your password. Fifteen bits of range on top of that makes it hopeless for a secret, which needs a source with far more state and no way to run it backwards.

## Step 2: The random device, and a pipeline that is subtly wrong

Linux exposes its randomness as a file. `/dev/urandom` returns bytes you cannot predict. The common way to turn that into text keeps only the characters you want.

```bash
tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 20
```

```text
7r93dJ0QBAEMQR6AglUm
```

`tr -dc 'A-Za-z0-9'` deletes every byte that is not a letter or a digit, and `head -c 20` stops after twenty bytes. This usually gives you twenty characters, and it is the idiom you will see in most guides. It is still subtly wrong. `head` exits the moment it has its twenty bytes and closes the pipe. `tr` is still writing at that point, so it is killed by a signal in the middle of its work. The result depends on that signal rather than on the two tools agreeing on a length. In a script that inspects the status of every stage, or on a system that buffers differently, the same line can report a broken pipe or return a short value. It also reads an unbounded amount from the device, because most of what it reads is thrown away. It works most of the time, but it is not the tool to reach for when you want a definite number of random characters.

<Callout type="tip" title="Prefer a tool that reads a set number of bytes">
A generator that asks the kernel for exactly the bytes it needs never has to be stopped from the far end of a pipe. That is what `openssl` and `secrets` both do.
</Callout>

## Step 3: The correct forms with openssl

`openssl` is a Termux package, and its `rand` subcommand writes random bytes and encodes them for you. Install it with `pkg install openssl` if `openssl version` is not found.

```bash
openssl rand -base64 24
```

```text
zEgHN/aHzOCVBp7o5OwYt5mHIsf4NMeN
```

This asks for 24 random bytes, which is 192 bits, and prints them in base64. Base64 takes three bytes and writes four characters, so 24 bytes become 32 characters. Because 24 divides exactly by three there is no padding on the end. Every character carries six bits.

```bash
openssl rand -hex 16
```

```text
5cdf6611dd3a6f20468ced08bb39471d
```

The same idea in hexadecimal. Sixteen bytes become 32 characters, because each byte is two hex digits, and each character carries four bits. Hex is safe in almost any context, a filename, a config file or a URL, while base64 is shorter for the same number of bits.

## Step 4: The Python version with secrets

Python has a module built for this job, called `secrets`, which draws from the same operating system randomness rather than from a seed you can set. Python is not part of the base install, so run `pkg install python` first if `python3` is not found.

```bash
python3 -c "import secrets, string; a = string.ascii_letters + string.digits; print(''.join(secrets.choice(a) for _ in range(20)))"
```

```text
VbTCkJvuO1rExncXWVu8
```

`secrets.choice` picks one character from a string, and the loop repeats it twenty times. The alphabet here is `string.ascii_letters + string.digits`, which is 26 lower case letters, 26 upper case letters and 10 digits, so 62 characters in all. Change the alphabet to add symbols and the password gets a little stronger; change the range to change the length.

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(16))"
```

```text
EcoNYAXAMkjdZzwmIxVmMQ
```

`token_urlsafe(16)` reads sixteen random bytes and encodes them with the URL safe base64 alphabet, which swaps `+` and `/` for characters that need no escaping in a URL. That gives 22 characters and 128 bits, and it is the right call for a token that will travel in a URL. For a password a person is going to type, the choice loop above reads more clearly.

## Step 5: Working out the entropy

Entropy in bits is the length times the log base 2 of the alphabet size. Each extra character multiplies the possibilities by the size of the alphabet, and a log base 2 turns that into a simple addition, so the bits add up. Work out the bits for one character of a 62 character alphabet with `awk`, which has a natural logarithm function.

```bash
awk 'BEGIN { print log(62)/log(2) }'
```

```text
5.9542
```

That is the bits each character contributes, about 5.95. Multiply it by the length.

```bash
awk 'BEGIN { print 20 * log(62)/log(2) }'
```

```text
119.084
```

Python has a log base 2 built in, so it does the same sum in one step.

```bash
python3 -c "import math; print(20 * math.log2(62))"
```

```text
119.0839262077375
```

So a twenty character password from letters and digits is about 119 bits. Compare that with the byte based forms. Twenty four random bytes in base64 is 192 bits, and sixteen random bytes in hex is 128 bits, because those counts come straight from the number of bytes at eight bits each. For a character based generator the total depends on both the length and the alphabet. Adding symbols lifts each character a little; adding length grows the total in proportion. Length is the easier lever, because it costs you nothing but a little more typing.

## Step 6: Why a read loop is worse

There is a third option people try: a loop that asks you to type the characters one at a time.

```bash
pw=""
while [ ${#pw} -lt 4 ]; do
  read -r -p "Add a character: " c
  pw="$pw$c"
done
echo "your password is: $pw"
```

If you type a, b, c and d in turn, you get this.

```text
your password is: abcd
```

This is the weakest of the three by a wide margin. The characters come from you, and people reach for the same keys every time: a name, a birthday, the top row of the keyboard. The loop also makes the length depend on how many times you happen to press enter, and it leaves the password sitting on the screen. A generator is worth using precisely because it draws from a source you cannot bias. If you want a secret you can hold in your head, use a long passphrase of several ordinary words, and let generated passwords cover the rest.

## Quick reference

| Command | What it does |
| --- | --- |
| `echo $RANDOM` | A shell number from 0 to 32767, seeded and repeatable |
| `tr -dc 'A-Za-z0-9' < /dev/urandom \| head -c 20` | Twenty characters from the random device, but it depends on `head` closing the pipe |
| `openssl rand -base64 24` | 24 random bytes as 32 base64 characters |
| `openssl rand -hex 16` | 16 random bytes as 32 hex characters |
| `python3 -c "... secrets.choice ..."` | A password from an alphabet you choose |
| `secrets.token_urlsafe(16)` | 16 bytes as 22 URL safe characters |
| `awk 'BEGIN { print log(N)/log(2) }'` | Bits per character for an alphabet of N |
| `python3 -c "import math; print(L * math.log2(N))"` | Total bits for length L and alphabet N |
