You do not need to type a single character to start. Each box below has some lines already written and one or more gaps. Tap a piece from the list and it drops into a gap, then press Run and the program executes right there on the page.

Every box starts with the switch **Put pieces in the right place for me** turned on. In that mode a piece you tap goes where it belongs, so you can never end up with a program that is broken for a reason you cannot see yet. Turn the switch off once you want to place them yourself, and the mistakes become yours to find, which is when the learning really starts.

## What you'll be able to do

- Put a program together from pieces without typing.
- Run Python and read what it prints.
- Place pieces in the right order without help.
- Read the error Python gives you when something is wrong.

## Step 1: Make it say something

`print` is the word that makes Python show you something. Tap the piece that belongs in the gap.

<PyBlanks
  title="Say hello"
  scaffold={`@1("Hello from Python")`}
  pieces={['len', 'print', 'input']}
  answers={[1]}
  expect="Hello from Python"
  hint="Two of those pieces ask the reader for something. One of them shows a value."
/>

The program is one line: the word `print`, then a pair of brackets with some text inside. The quotes tell Python the text is literal characters rather than a name to look up.

Now turn the switch off and press Reset, then put the pieces back yourself. Same program, but now you chose it.

## Step 2: Store a value

A name on the left of an `=` holds whatever is on the right. Fill both gaps so the program works out the minutes in a day and prints it.

<PyBlanks
  title="Minutes in a day"
  scaffold={`minutes = @1
print(@2)`}
  pieces={['minutes', '60 * 24', '"minutes"', '1440']}
  answers={[1, 0]}
  expect="1440"
  hint="The first gap is a sum Python works out. The second is the name you just stored it under."
/>

Two of those pieces are wrong on purpose. `"minutes"` is the word itself, in quotes, which is text rather than the number. `1440` would work, but then Python has not done the arithmetic and you have not learned anything. Tap a wrong piece in guided mode and it will tell you so.

## Step 3: Repeat a line

This is the loop, and it is the shape most beginners find hardest. Two gaps, two pieces, and the order matters.

<PyBlanks
  title="Add them up"
  scaffold={`total = 0
for i in range(1, 101):
    @1
@2`}
  pieces={['print(total)', 'total += i']}
  answers={[1, 0]}
  expect="5050"
  hint="One piece belongs inside the loop, indented under it. The other comes after the loop has finished."
/>

Read the indentation, because it is doing the work. The line indented under `for` runs a hundred times, once for each number. The line at the left edge runs once, after the loop has finished.

`total += i` means "add `i` to `total` and store it back". It is shorthand for `total = total + i`.

Put them the wrong way round with the switch off and press Run. You will get a hundred numbers instead of one, which shows exactly what the indentation controls.

## Step 4: Now type one yourself

Placing pieces teaches you the shape. Typing teaches you the vocabulary. This box is empty on purpose, and you can edit it.

<PyCell
  title="Your turn to type"
  code={`print("I typed this myself")`}
/>

Change the words inside the quotes and press Run. The quotes have to stay, or Python looks for a name and fails.

## Step 5: A mistake, and what Python says about it

This one is broken already. Press Run and read the last line of what comes back.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="Hello, Termux"
  hint="Python is case sensitive. Compare the name on the first line with the name on the second."
  code={`name = "Termux"
print("Hello, " + Name)`}
  solution={`name = "Termux"
print("Hello, " + name)`}
/>

The last line reads `NameError: name 'Name' is not defined`. Read that line first, every time, because it names the problem exactly. Something called `Name` was used but never created. There is a `name` above it with a lowercase `n`, and Python treats those as two entirely different names.

Fix it and press Run. The box marks itself when it prints `Hello, Termux`.

## Step 6: Put a function together

A function is a named block you can call. One gap here, and three pieces, only one of which belongs.

<PyBlanks
  title="A function"
  scaffold={`def area(width, height):
    @1

print(area(3, 4))`}
  pieces={['return width * height', 'print(width * height)', 'width + height']}
  answers={[0]}
  expect="12"
  hint="A function hands a value back to whoever called it. Only one of these words does that."
/>

`return` is what sends the value back to the caller, which is why `print(area(3, 4))` has something to print. Without it the function returns nothing, and the print gets nothing to show.

Write a function that hands a word back reversed, then print the reversed form of `Termux`. The answer is `xumreT`.

## Quick reference

| Piece | What it does |
| --- | --- |
| `print(...)` | show a value |
| `name = value` | store a value under a name |
| `"text"` | literal characters, not a name |
| `total += i` | add to a running total |
| four spaces | what puts a line inside a loop or a function |
| `def` and `return` | define a function, and hand a value back |
| `word[::-1]` | the whole string, walked backwards |
| the last line of a traceback | what actually went wrong |
