The `ipaddress` module in the standard library does subnet arithmetic for you, and it does it correctly, including the two cases most people get wrong. In this lesson you will build an address object, make a network from a string, read the netmask, the broadcast address and the address count, list the usable hosts, split a /24 into /26s, and see how a /31 and a /32 behave. Every cell runs Python inside this page, so you can change an address and run it again.

The figures here match the site's subnet calculator and the [Build a subnet calculator](/learn/build-a-subnet-calculator/) lesson, because it is the same arithmetic in every case. Where this lesson and the shell lesson agree, that is the check working, not a coincidence.

## What you'll be able to do

- Make an address object and read it as text and as a number.
- Build a network with `ip_network`, and use `strict=False` when you start from a host address.
- Read the netmask, the broadcast address and how many addresses a block holds.
- List the usable hosts with `hosts()`.
- Split a network into longer prefixes with `subnets(new_prefix=26)`.
- Explain what a /31 and a /32 mean, and why `hosts()` behaves differently there.

## Step 1: An address is an object

`ip_address` takes a string and gives you back an object that knows things about itself: which version of IP it is, and what the whole thing looks like as one integer.

<PyCell
  title="Make an address"
  code={`import ipaddress
addr = ipaddress.ip_address("192.168.1.42")
print(addr)
print(addr.version, int(addr))`}
/>

The first line prints the address back in its normal form. The second prints `4` for the version and `3232235818`, which is the same address written as a single 32-bit number. That number is the one the shell lesson builds by hand with `awk`; here the module hands it to you. Four numbers between 0 and 255, each worth one byte, multiplied by their place values and added up.

## Step 2: A network from a string

`ip_network` reads an address with a prefix and gives you the network it belongs to. From that one object you can read the netmask, the broadcast address and how many addresses it holds.

<PyCell
  title="A network and its figures"
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(net)
print(net.netmask)
print(net.broadcast_address)
print(net.num_addresses)`}
/>

`net` prints as `192.168.1.0/24`. The `.42` host bits were cleared, because a network address has every host bit set to zero. The netmask is `255.255.255.0`, the broadcast address is `192.168.1.255`, and `num_addresses` is `256`. The calculator reports `254` usable hosts for the same block, because the network and the broadcast address are reserved and cannot be given to a machine.

The `strict=False` matters. Without it, `ip_network` refuses an address that is not the network address itself, because `192.168.1.42` is a host inside the network rather than the network's own address. Passing `strict=False` tells the module you know that, and it rounds down for you.

## Step 3: Counting addresses

The address count is two to the power of the host bits. A longer prefix leaves fewer host bits and so fewer addresses.

<PyCell
  title="How many addresses"
  expect={`24 256\n26 64\n31 2\n32 1`}
  hint="Print the prefix and net.num_addresses on the same line, once per loop."
  code={`import ipaddress
for prefix in (24, 26, 31, 32):
    net = ipaddress.ip_network(f"192.0.2.0/{prefix}")
    print(prefix, net.num_addresses)`}
/>

A /24 leaves 8 host bits, so 256 addresses. A /26 leaves 6, so 64. A /31 leaves 1 bit and a /32 leaves none, which is where the counts get small enough to need a special rule, and that rule is the subject of Step 7. These are the same totals the calculator prints, including the tiny /31 and /32.

## Step 4: The hosts in a network

`hosts()` yields the addresses that can be assigned to a machine. For an ordinary network that is every address except the network and the broadcast addresses.

<PyCell
  title="Usable hosts in a /29"
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.0/29")
hosts = list(net.hosts())
print(net.num_addresses, len(hosts))
print(hosts[0], hosts[-1])`}
/>

A /29 holds 8 addresses, and `hosts()` yields 6 of them, because two are reserved. The first usable host is `192.168.1.1` and the last is `192.168.1.6`. Those match the `first host` and `last host` rows the calculator prints. `hosts()` is a generator, so wrap it in `list()` when you need to index it or count it more than once.

## Step 5: Count the usable hosts

`len` on the host list gives you the usable host count, which is the number the calculator shows as `Usable hosts`.

<PyCell
  title="Usable hosts in a /24"
  expect="254"
  hint="Turn hosts() into a list and take its length."
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.0/24")
print(len(list(net.hosts())))`}
/>

A /24 holds 256 addresses, and `hosts()` yields 254 of them, because the network and the broadcast addresses are left out. That is the `total - 2` the shell lesson works out by hand, and it is the same 254 the calculator reports. For a /31 or a /32 the subtraction does not apply, and Step 8 shows why.

## Step 6: Split a /24 into /26s

`subnets(new_prefix=26)` cuts a network into smaller networks of a longer prefix. Four /26 blocks fit inside one /24, and each holds 64 addresses.

<PyCell
  title="Four /26 subnets"
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.0/24")
subs = list(net.subnets(new_prefix=26))
print(len(subs))
for s in subs:
    print(s)`}
/>

The four blocks step by 64: `192.168.1.0/26`, then `.64`, then `.128`, then `.192`. That step is the size of a /26, which is 64 addresses. This is exactly what the calculator's `Split it further` panel does when you leave the new prefix at 26, and the blocks line up one for one.

## Step 7: The third /26

This cell prints the wrong block. Work out which index gives the third subnet and fix it.

<PyCell
  title="The third /26"
  expect="192.168.1.128/26"
  hint="Python counts list positions from zero, so the third item is not at index three."
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.0/24")
subs = list(net.subnets(new_prefix=26))
print(subs[3])`}
  solution={`import ipaddress
net = ipaddress.ip_network("192.168.1.0/24")
subs = list(net.subnets(new_prefix=26))
print(subs[2])`}
/>

The starter prints `192.168.1.192/26`, which is the fourth block, because `subs[3]` counts from zero. The third block is `subs[2]`, which is `192.168.1.128/26`. This off-by-one is worth meeting once here, where the output is easy to read, rather than in a firewall rule where it is not.

## Step 8: The /31 and /32 cases

A /31 has two addresses and a /32 has one. There is no room to reserve a network or a broadcast address in either, so the rules change: every address in the block is usable.

<PyCell
  title="/31 and /32"
  code={`import ipaddress
link = ipaddress.ip_network("10.0.0.4/31")
print(link.netmask, link.broadcast_address)
print(list(link.hosts()))
host = ipaddress.ip_network("192.0.2.9/32")
print(host.netmask, host.broadcast_address)
print(list(host.hosts()))`}
/>

For the /31, the netmask is `255.255.255.254` and the broadcast address is `10.0.0.5`, the second of the two addresses. `hosts()` returns both `10.0.0.4` and `10.0.0.5`, because on a point-to-point link both ends are machines. For the /32, the netmask is `255.255.255.255` and the address is both the network and the host, so `hosts()` returns that one address. The calculator agrees: it reports 2 usable hosts for a /31 and 1 for a /32. Many calculators subtract two from a /31 and report zero, which is wrong, and this module does not.

## Step 9: Find the mistake

This cell raises an error. Read the message, work out why, and fix it.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="192.168.1.0/24"
  hint="192.168.1.42 is a host inside the network, not the network address itself."
  code={`import ipaddress
net = ipaddress.ip_network("192.168.1.42/24")
print(net)`}
  solution={`import ipaddress
net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(net)`}
/>

The error is `ValueError: 192.168.1.42/24 has host bits set`. `ip_network` will not quietly discard the host bits for you, because doing so hides a mistake in a config file. Adding `strict=False` says you meant a host address and want the network it sits in, and the output becomes `192.168.1.0/24`. When the address already is a network address, both forms give the same answer and `strict` makes no difference.

## Quick reference

| Piece | What it does |
| --- | --- |
| `ipaddress.ip_address("192.168.1.42")` | An address object, with `.version` and `int()` |
| `ipaddress.ip_network("192.168.1.0/24")` | The network for a CIDR string |
| `strict=False` | Accept a host address and round down to the network |
| `net.netmask` | The subnet mask, for example `255.255.255.0` |
| `net.broadcast_address` | The last address in the block |
| `net.num_addresses` | How many addresses the block holds |
| `net.hosts()` | The usable host addresses, as a generator |
| `net.subnets(new_prefix=26)` | Split into smaller blocks of a longer prefix |
| `/31` and `/32` | Two usable addresses, and one, with nothing reserved |
