Subnetting is bit arithmetic, and bit arithmetic done by hand on a phone is a way to make mistakes. Python ships a module that does all of it, correctly, including the two cases people get wrong: a `/31` and a `/32`.

Every box below starts with the pieces placed for you. Turn that off once the shapes are familiar.

## What you'll be able to do

- Build a network from an address and a prefix.
- Read the netmask, the broadcast address and the host count off it.
- Split a network into smaller ones.
- Handle a `/31` and a `/32` the way the RFCs actually say.

## Step 1: Make a network

An address on its own is not a network. You need the prefix, and you need to tell the module what to do when the address has host bits set.

<PyBlanks
  title="A network from an address"
  scaffold={`import ipaddress

net = ipaddress.ip_network("192.168.1.42/24", @1)
print(net)`}
  pieces={['strict=True', 'strict=False', 'relaxed=True']}
  answers={[1]}
  expect="192.168.1.0/24"
  hint="By default the module refuses an address with host bits set. You want it to accept one."/>

`192.168.1.42/24` is an address, not a network, because `.42` is a host bit. With `strict=True`, which is the default, the module raises `ValueError: 192.168.1.42/24 has host bits set`. With `strict=False` it works out the network the address belongs to: `192.168.1.0/24`.

## Step 2: The mask

The netmask is the prefix written out in full.

<PyBlanks
  title="The netmask"
  scaffold={`import ipaddress

net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(net.@1)`}
  pieces={['broadcast_address', 'netmask', 'num_addresses']}
  answers={[1]}
  expect="255.255.255.0"
  hint="You want the mask itself, not a count and not the last address."/>

Twenty-four ones followed by eight zeros. `net.prefixlen` gives you the `24` back, and `net.hostmask` gives the inverse, `0.0.0.255`, which is the wildcard mask you meet in firewall rules.

## Step 3: The broadcast address

The last address in the block has every host bit set.

<PyBlanks
  title="The broadcast address"
  scaffold={`import ipaddress

net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(net.@1)`}
  pieces={['network_address', 'broadcast_address', 'hostmask']}
  answers={[1]}
  expect="192.168.1.255"
  hint="The highest address in the block."/>

`net.network_address` is the other end, `192.168.1.0`. Those two are the addresses a host cannot have, which is why the usable count is two lower than the block size.

## Step 4: How many hosts

Counting them is where the module earns its keep, because it knows the special cases.

<PyBlanks
  title="Usable hosts"
  scaffold={`import ipaddress

net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(len(list(net.@1())))`}
  pieces={['subnets', 'hosts', 'addresses']}
  answers={[1]}
  expect="254"
  hint="Which method hands you the addresses a machine can actually be given?"/>

254. The block holds 256 addresses, and the network and broadcast addresses are not among them. `net.num_addresses` is 256, which is the number people quote when they mean the block size rather than the host count.

## Step 5: Split it up

`subnets` cuts a network into smaller ones of a given prefix.

<PyBlanks
  title="Four /26 blocks"
  scaffold={`import ipaddress

net = ipaddress.ip_network("192.168.1.42/24", strict=False)
print(len(list(net.@1(new_prefix=26))))`}
  pieces={['subnets', 'hosts', 'supernet']}
  answers={[0]}
  expect="4"
  hint="Going from /24 to /26 borrows two more bits, so the count goes up by four."/>

A `/24` holds four `/26` blocks, each with 64 addresses. Going the other way, `supernet`, gives you the larger block a network sits inside. Borrowing bits doubles the count for every bit you take, which is the one piece of arithmetic worth holding in your head.

## Step 6: The case most calculators get wrong

A `/31` has two addresses and **both** are usable, because there is no room to reserve a network or a broadcast address. RFC 3021 defines this for point-to-point links.

<PyBlanks
  title="Both usable"
  scaffold={`import ipaddress

net = ipaddress.ip_network("10.0.0.4/31")
print(len(list(net.@1())))`}
  pieces={['hosts', 'subnets']}
  answers={[0]}
  expect="2"
  hint="The module already knows the RFC. Just ask it for the hosts."/>

Two, not zero. Plenty of subnet calculators subtract two from a `/31` and cheerfully report that no host can be given an address, which is wrong. The module gets it right because it follows the RFC rather than the folk rule.

## Step 8: A mistake to find

This one raises. Press Run and read the last line.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="192.168.1.0/24"
  hint="An address with host bits set is not a network. The module is strict by default."
  code={`import ipaddress

print(ipaddress.ip_network("192.168.1.42/24"))`}
  solution={`import ipaddress
print(ipaddress.ip_network("192.168.1.42/24", strict=False))`}
/>

`ValueError: 192.168.1.42/24 has host bits set`. The module is telling you that you handed it an address and asked for a network. Either give it a real network address, or say `strict=False` and let it work out which network you meant.

## Quick reference

| Piece | What it does |
| --- | --- |
| `ip_network("10.0.0.0/8")` | a network, strict by default |
| `strict=False` | accept an address with host bits set |
| `net.netmask` | the mask in full, `255.255.255.0` |
| `net.hostmask` | the inverse, `0.0.0.255` |
| `net.network_address` | the lowest address |
| `net.broadcast_address` | the highest address |
| `net.num_addresses` | the block size |
| `net.hosts()` | the addresses a machine can be given |
| `net.subnets(new_prefix=26)` | smaller blocks inside it |
| a `/31` | two usable addresses, per RFC 3021 |
