A secret is any value that would cause trouble if the wrong person saw it: an API token, a session key, a password. This lesson is about handling those values in Python. By the end you will be able to keep a secret out of your source code, generate a strong token when you need one, turn a secret into a hash before you store it, and compare two tokens without giving an attacker a timing signal. The code cells run in your browser in real CPython, so you can run each one and read its output as you go.

## What you'll be able to do

- Read a secret from the environment instead of writing it into the file.
- Explain why a token belongs in the environment and not in the source.
- Generate a strong token with the `secrets` module, and say why `random` is the wrong tool for it.
- Turn a secret into a SHA-256 hash so the stored form is not the secret.
- Compare two tokens with a constant time check.
- Recognise the two mistakes that leak a secret: hardcoding it, and comparing it with `==`.

## Step 1: A secret does not belong in the file

If you write `API_TOKEN = "abc123"` at the top of a script, that value is now in your source, in your editor history, and in any copy of the file you send to someone. The environment is where it belongs, because it lives outside the file and is set for the session rather than baked into the code.

<PyCell
  title="Read a secret from the environment"
  code={`import os
api = os.environ.get("API_TOKEN", "missing")
print("token present:", api != "missing")`}
/>

`os.environ` is the Python view of the environment, the same set of names the shell shows you with `env`. `get` takes a default as its second argument, so if `API_TOKEN` is not set you get `"missing"` rather than a crash. Here nothing is set, so the output is `token present: False`. Notice that the code never prints the secret itself; a script that logs its own token is a script that leaks it.

## Step 2: Generate a token when you need one

When you need to create a secret, do not invent one in your head. The `secrets` module is made for exactly this, and it draws from the operating system's source of randomness.

<PyCell
  title="Generate a token with token_hex"
  code={`import secrets
token = secrets.token_hex(8)
print(len(token))
print(token.isalnum())`}
/>

`token_hex(8)` produces 8 random bytes and prints each one as two hexadecimal digits, so the result is 16 characters long and made only of letters and digits. That is why `isalnum()` is `True`. The shell equivalent you may have seen is `openssl rand -hex 8`, and the idea is the same: ask the system for random bytes rather than making them up.

## Step 3: A token you can put in a URL

Sometimes the token travels in a URL or a cookie, where a few characters like `+` and `/` cause trouble. `token_urlsafe` gives you a token that is safe to put in those places.

<PyCell
  title="Generate a token with token_urlsafe"
  code={`import secrets
token = secrets.token_urlsafe(12)
print(len(token))`}
/>

`token_urlsafe(12)` takes 12 bytes and encodes them in a URL-safe alphabet, which comes out as 16 characters. The exact characters change every run, which is the point, but the length is fixed, so this cell always prints `16`. If you needed to compare two runs you would compare their lengths, never their contents, because the contents are meant to be unpredictable.

## Step 4: A checkpoint on token length

This checkpoint already produces the output it expects, so it marks itself correct when you run it. Change the argument to `token_hex` and run it again to see the length change.

<PyCell
  title="Token length from the byte count"
  expect="32"
  code={`import secrets
token = secrets.token_hex(16)
print(len(token))`}
/>

Sixteen bytes, two characters each, is 32 characters. Holding that relationship in your head is useful, because the argument you pass to `token_hex` is a count of bytes, not a count of characters.

## Step 5: Store a hash, not the secret

If you have to keep a token somewhere, keep a hash of it. A hash is a fixed-length fingerprint: the same input always gives the same output, and you cannot run it backwards to recover the input. Storing the fingerprint means a leaked database does not hand over the tokens.

<PyCell
  title="Hash a secret with SHA-256"
  code={`import hashlib
token = "s3cr3t-token"
digest = hashlib.sha256(token.encode()).hexdigest()
print(len(digest))
print(digest[:8])`}
/>

The `.encode()` matters: a hash works on bytes, and a string in Python is text, so you convert first. The digest is 64 hexadecimal characters, because SHA-256 is 256 bits and each hex character carries four of them. `digest[:8]` prints the first eight characters as a short preview. A hash is not encryption: there is no key and no way back, which is exactly what you want for a value you only ever need to check against.

## Step 6: A checkpoint on digest length

Another self-checking cell. It hashes a fixed piece of text and prints the length of the result.

<PyCell
  title="A digest is always the same length"
  expect="64"
  code={`import hashlib
print(len(hashlib.sha256(b"anything").hexdigest()))`}
/>

No matter what you hash, the answer is 64 characters, because SHA-256 always produces 256 bits. The `b` before the quote makes it a bytes literal, which is the form the hasher wants. Try replacing the text and watch the length stay at 64 while the value changes.

## Step 7: Find the mistake

This cell asks for a token that is 32 characters long, but it prints something else. The code is not broken in the sense of raising an error; it is simply asking for the wrong size. Read it, work out what the argument means, and fix it.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="32"
  hint="token_hex takes a count of bytes, and each byte prints as two characters."
  code={`import secrets
token = secrets.token_hex(32)
print(len(token))`}
  solution={`import secrets
token = secrets.token_hex(16)
print(len(token))`}
/>

The code asked for 32 bytes, which printed as 64 characters. To get 32 characters you ask for 16 bytes. The mistake is easy to make because the number in the call looks like a length when it is really a byte count.

## Step 8: Your turn: hash the token from the environment

Now combine the first two ideas. Read a token from the environment with a default, then print its SHA-256 digest as hex. The starter is incomplete, so it prints nothing until you add the hashing line.

<PyCell
  title="Hash the token from the environment"
  expect="0cd48eed49739dfdd99efaef37d251aae5a80866e5954763c6597943fff5ce9b"
  hint="Use hashlib.sha256 on the encoded token, and print the hexdigest."
  code={`import os, hashlib
token = os.environ.get("API_TOKEN", "local-dev-token")
# Your turn: print the SHA-256 digest of the token, as hex.`}
  solution={`import os, hashlib
token = os.environ.get("API_TOKEN", "local-dev-token")
print(hashlib.sha256(token.encode()).hexdigest())`}
/>

The token comes from the environment when it is set and falls back to a development value when it is not, so the script never carries a real secret in its source. The digest is what you would store. Because the default is fixed, this cell prints the same digest every run, which is what makes it checkable.

## Step 9: Your turn: compare tokens safely

The last exercise is about the check you do when a token arrives and you want to know whether it matches the one you stored. The starter is incomplete, so it prints nothing until you add the comparison.

<PyCell
  title="Compare two tokens safely"
  expect="True"
  hint="hmac.compare_digest returns a boolean, and it takes the same time whatever the two values are."
  code={`import hmac
stored = "token-abc"
given = "token-abc"
# Your turn: print True only if they match, using a constant time check.`}
  solution={`import hmac
stored = "token-abc"
given = "token-abc"
print(hmac.compare_digest(stored, given))`}
/>

The two values match, so it prints `True`. The reason to use `hmac.compare_digest` instead of `==` is timing: a plain comparison stops at the first character that differs, so how long it takes hints at how much of the value was right. `compare_digest` looks at every character either way, so the time it takes does not reveal anything. For a single check the difference is invisible; for a token an attacker can try over and over, it is the difference between guessing and measuring.

## Quick reference

| Piece | What it does |
| --- | --- |
| `os.environ.get("NAME", default)` | read a value from the environment, with a fallback |
| `secrets.token_hex(n)` | `2n` random hex characters from `n` bytes |
| `secrets.token_urlsafe(n)` | a URL-safe token from `n` bytes |
| `secrets.choice(seq)` | pick one item at random, safely |
| `hashlib.sha256(data).hexdigest()` | the 64-character SHA-256 fingerprint of some bytes |
| `value.encode()` | turn a string into bytes for hashing |
| `hmac.compare_digest(a, b)` | compare two values in constant time |
| `==` | compare two values, but stops at the first difference |
