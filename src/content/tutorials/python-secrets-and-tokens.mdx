Anything a person uses as a secret has to come from a source an attacker cannot predict. Python has two modules for randomness and only one of them is safe for this. Every program below uses the safe one, and the last one puts the pieces together into a small tool.

## What you'll be able to do

- Generate a token with `secrets` and know why not `random`.
- Work out how many characters a byte count produces.
- Hash a token so you can store the digest instead of the token.
- Compare two secrets without leaking timing.
- Read a secret from the environment instead of the source.

## Step 1: Two token functions, two lengths

`secrets` has two ways to make a token, and the length you get back depends on which one you use.

<PyBlanks
  title="Hex and URL-safe tokens"
  scaffold={`import secrets

hex_token = secrets.@1(16)
url_token = secrets.@2(12)

print(len(hex_token))
print(len(url_token))`}
  pieces={['token_urlsafe', 'token_hex', 'randbelow']}
  answers={[1, 0]}
  expect={`32
16`}
  hint="One gives hex characters, two per byte. The other packs four bytes into three characters."
/>

Seven lines, two figures: 32 and 16. `token_hex(16)` is 16 bytes written as two hex characters each. `token_urlsafe(12)` is 12 bytes packed four into three, which rounds up to 16 characters.

The number you pass is **bytes**, not characters. That is the trap, and it is the one a beginner hits.

`random` would give you something that looks just as random and is not. It is seeded from a value an attacker can often work out, and it is built for shuffling cards rather than for making secrets.

## Step 2: Hash the token, keep the digest

A server should not store the token itself. It stores a digest and compares digests later.

<PyBlanks
  title="Store the digest"
  scaffold={`import hashlib

token = b"local-dev-token"
digest = hashlib.sha256(@1).hexdigest()

print(len(digest))
print(@2)`}
  pieces={['digest[:8]', 'token', '"local-dev-token"']}
  answers={[1, 0]}
  expect={`64
0cd48eed`}
  hint="One gap is already bytes. The other shows the first eight characters of the digest."
/>

Seven lines. 64 is always the answer for SHA-256, because it is 32 bytes written as hex. Storing the digest means a database leak does not hand over working tokens.

Note the gap takes `token`, not the string in quotes. `token` is already bytes because of the `b` on line three; retyping the string without the `b` would raise `TypeError: Strings must be encoded before hashing`.

## Step 3: Compare without leaking

Comparing two secrets with `==` stops at the first difference, so it takes slightly longer the more characters match. Over enough attempts that timing is information.

<PyBlanks
  title="Compare two tokens"
  scaffold={`import hmac

a = "token-abc"
b = "token-abc"
c = "token-abd"

print("same:", @1)
print("different:", @2)`}
  pieces={['hmac.compare_digest(a, c)', 'hmac.compare_digest(a, b)']}
  answers={[1, 0]}
  expect={`same: True
different: False`}
  hint="Both gaps use the same function. One compares two values that match, one compares values that differ by a letter."
/>

Eight lines, and the two answers differ by one character. `compare_digest` takes the same time whether the first character differs or the last one does, which is the whole point: it costs nothing and it closes a hole.

## Step 4: Read the secret from the environment

A secret in your source code is a secret in your git history. Read it from the environment instead, and handle the case where it is not there.

<PyBlanks
  title="A secret that may be missing"
  scaffold={`import os

token = os.environ.@1("LEARMUX_DEMO_TOKEN")

if token is @2:
    print(@3)
else:
    print("a token is set")`}
  pieces={['None', 'get', '"no token set"', 'True']}
  answers={[1, 0, 2]}
  expect="no token set"
  hint="One gap reads the variable. One is the value you get when it is missing. One is the message to print."
/>

Eight lines with a branch. `os.environ.get` returns `None` when the name is missing, which is why the test reads `is None` rather than `== ""`. An empty string means the variable is set to nothing, which is a different situation from it not being set at all.

Run it here and you get `no token set`, because there is no such variable in this page's environment. That is the branch working, not a failure.

## Step 5: A small tool that uses all of it

Now a function, a token, and two facts about it. This is the shape of a real script.

<PyBlanks
  title="Token and fingerprint"
  scaffold={`import hashlib
import secrets

def fingerprint(token):
    return hashlib.sha256(token.encode()).hexdigest()[:8]

token = secrets.token_hex(16)

print("length", @1)
print("fingerprint length", @2)`}
  pieces={['len(token)', 'len(fingerprint(token))', 'len(fingerprint)']}
  answers={[0, 1]}
  expect={`length 32
fingerprint length 8`}
  hint="One gap is the length of the token. The other is the length of what the function returns for it."
/>

Ten lines. The token is different every time you press Run, and both printed figures stay the same, which is the useful property: the value changes, its shape does not.

`len(fingerprint)` without the brackets would give you an error rather than a length, because a function is not a string. That is the third piece, and it is there to be tried.

## Step 7: A mistake to find

The code runs and prints something, but the number is wrong. Press Run and look at it.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="32"
  hint="The argument is bytes, and the answer is hex characters. Two per byte."
  code={`import secrets

token = secrets.token_hex(8)
print(len(token))`}
  solution={`import secrets
token = secrets.token_hex(16)
print(len(token))`}
/>

It prints 16, not 32. Nothing raised, so the only way to notice is to know that a hex token is twice as long as the bytes it came from. That is exactly the kind of quiet mistake a test catches and a person does not.

## Quick reference

| Piece | What it does |
| --- | --- |
| `secrets.token_hex(n)` | n bytes as 2n hex characters |
| `secrets.token_urlsafe(n)` | n bytes as a URL-safe string, rounded up |
| `random` | not for secrets, ever |
| `hashlib.sha256(b"...")` | a digest, which needs bytes |
| `.hexdigest()` | always 64 hex characters for SHA-256 |
| `hmac.compare_digest(a, b)` | compare without leaking timing |
| `os.environ.get("NAME")` | `None` when it is not set |
| `if token is None:` | the branch for a missing secret |
| `digest[:8]` | a short digest for a screen |
