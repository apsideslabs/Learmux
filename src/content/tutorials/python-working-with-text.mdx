Most of what a script does is move text around: take a line apart, keep one field, put the fields back in a different order, print the result. Python has a small set of tools for that, and this lesson is about the five you will reach for constantly.

Every box below starts with the pieces placed for you. Turn that off once the shapes look familiar and do it yourself.

## What you'll be able to do

- Pick a single character or a slice out of a string.
- Split a line into fields, and join fields back into a line.
- Build text with an f-string instead of gluing pieces together.
- Recognise why a method changed nothing.

## Step 1: A string is a sequence

A string is characters in order, and each one has a position. Position counting starts at zero, which is the first thing to get used to.

<PyBlanks
  title="First character"
  scaffold={`word = "Termux"
print(@1)`}
  pieces={['word[1]', 'word[0]', 'word[-2]']}
  answers={[1]}
  expect="T"
  hint="Counting starts at zero, so the first character is at position zero."
/>

`word[0]` is `T` and `word[1]` is `e`. A negative index counts back from the end, so `word[-1]` is the last character. That trips up everybody once.

## Step 2: Take a slice

A slice takes a run of characters. `[start:stop]` gives you everything from `start` up to but **not including** `stop`.

<PyBlanks
  title="Three characters"
  scaffold={`code = "INV-2026-0042"
print(@1)`}
  pieces={['code[3:]', 'code[:3]', 'code[-3:]']}
  answers={[1]}
  expect="INV"
  hint="Everything up to position three, not including it."
/>

`code[:3]` is the first three characters. `code[3:]` is everything from position three onwards, which is the date. `code[-3:]` is the last three. The same three-part idea with a step, `[::2]`, takes every other character.

## Step 3: Split a line into fields

A colon-separated system file, the kind that holds one account per line, is really a row of fields. `split` turns one string into a list of them.

<PyBlanks
  title="First field"
  scaffold={`line = "root:x:0:0:root:/root:/bin/sh"
fields = line.@1(":")
print(fields[0])`}
  pieces={['join', 'split', 'strip']}
  answers={[1]}
  expect="root"
  hint="Which of those three takes a string apart rather than putting it together?"
/>

`fields` is now a list of seven strings, and `fields[0]` is the first. This is the Python version of `cut -d: -f1`, with one difference worth remembering: in the shell you write a new pipeline for each field, while here you split once and index the list as often as you like.

## Step 4: Join fields back together

`join` is the reverse. It takes a list and a separator, and it is written the way round that surprises people: the separator comes first.

<PyBlanks
  title="Join with dashes"
  scaffold={`parts = ["one", "two", "three"]
print(@1)`}
  pieces={['parts.join("-")', '"-".join(parts)', '"-" + parts']}
  answers={[1]}
  expect="one-two-three"
  hint="The separator is the thing doing the joining, so it goes first."
/>

`"-".join(parts)` says: take this dash and use it to join this list. `parts.join("-")` is the natural guess and it fails, because a list has no such method. That is worth remembering, because it is the mistake almost everyone makes first.

## Step 5: Build text with an f-string

Gluing strings with `+` gets unreadable fast, and it breaks outright when one of the pieces is a number. An f-string puts the values inside the text.

<PyBlanks
  title="An f-string"
  scaffold={`name = "Termux"
version = 0.118
print(@1)`}
  pieces={['"{name} {version}"', 'f"{name} {version}"', 'name + " " + version']}
  answers={[1]}
  expect="Termux 0.118"
  hint="Only one of those three puts the values into the text. One of them raises an error instead."
/>

The `f` before the quote is the whole trick. Without it the braces are literal characters. And `name + " " + version` raises a `TypeError`, because you cannot glue a string to a number with `+`. The f-string converts for you.

## Step 6: A method never changes the string

This one catches people coming from other languages. A method returns a **new** string and leaves the original alone.

<PyBlanks
  title="Clean a field"
  scaffold={`raw = "  Admin  "
print(@1)`}
  pieces={['raw.strip().lower()', 'raw.strip().lower', 'raw.strip']}
  answers={[0]}
  expect="admin"
  hint="Two of those are missing the brackets, so they hand back the method rather than calling it."
/>

`raw.strip()` removes the spaces from both ends, and `.lower()` folds the capitals. Both return a new string; `raw` itself is untouched. Chaining works because each call returns something the next one can use.

Without the brackets you get a description of the method rather than its result, which is a confusing thing to see printed.

## Step 7: Type one yourself

The shapes are the same. Now write one without the palette, using `split` and `join` together to turn a dotted address into a dashed one.

<PyCell
  title="Dots to dashes"
  expect="192-168-1-1"
  hint="Split on the dot, then join with a dash: '-'.join(address.split('.'))"
  code={`address = "192.168.1.1"

# Your turn: print the same address with dashes instead of dots.
`}
  solution={`address = "192.168.1.1"
print("-".join(address.split(".")))`}
/>

## Step 8: A mistake to find

One character is wrong here. Press Run and read the last line.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="admin:user"
  hint="The string inside the join is what goes between the pieces. There is nothing there."
  code={`line = "admin:user"
print("".join(line.split(":")))`}
  solution={`line = "admin:user"
print(":".join(line.split(":")))`}
/>

It prints `adminuser`, with the colon gone, because the string inside the brackets is what goes between the pieces and that string is empty. Put the colon back and the two halves are joined properly. This is the quiet kind of mistake: the code runs, nothing raises, and the only clue is the output.

## Quick reference

| Piece | What it does |
| --- | --- |
| `word[0]` | the first character |
| `word[-1]` | the last character |
| `code[:3]` | the first three characters |
| `code[3:]` | everything from position three |
| `line.split(":")` | a string into a list of fields |
| `"-".join(parts)` | a list of fields into a string |
| `f"{name} {version}"` | values inside the text |
| `raw.strip().lower()` | methods chain, and each returns something new |
| the last line of a traceback | what actually went wrong |
