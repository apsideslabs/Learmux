Most of what a script does is move text around: take a line apart, keep the field you want, put the fields back in a different order, print the result. Every program below is that job, six to eight lines long, with a few gaps to fill.

## What you'll be able to do

- Pick a slice out of a string and know what the numbers mean.
- Take a record apart with `split` and read one field out of it.
- Put fields back together with `join`, the right way round.
- Loop over a list of lines and build a second list from them.

## Step 1: Three slices out of one string

A slice is `[start:stop]`, and it stops **before** the position you name. Three gaps, three slices, one printed line.

<PyBlanks
  title="Three fields from one code"
  scaffold={`code = "INV-2026-0042"

kind = @1
year = @2
number = @3

print(kind, year, number)`}
  pieces={['code[-4:]', 'code[:3]', 'code[4:8]', 'code[3:]']}
  answers={[1, 2, 0]}
  expect="INV 2026 0042"
  hint="The first three characters, then four characters starting at position four, then the last four."
/>

`code[:3]` is `INV`. `code[4:8]` starts at position four and stops before eight, which gives the year. `code[-4:]` counts four back from the end. One piece is wrong on purpose: `code[3:]` would run to the end of the string and swallow the rest.

Counting starts at zero, so position four is the fifth character. That is why the year starts at four and not at five: there is a dash at position three.

## Step 2: A record is a row of fields

This is a real account line, seven fields separated by colons. Split it once, then read three of them.

<PyBlanks
  title="Read a record"
  scaffold={`line = "root:x:0:0:root:/root:/bin/sh"
fields = line.@1(":")

name = @2
uid = @3
home = fields[5]

print(name, uid, home)`}
  pieces={['fields[0]', 'split', 'fields[2]', 'fields[1]']}
  answers={[1, 0, 2]}
  expect="root 0 /root"
  hint="The name is the first field. The user id is the third, because there is a password field in between."
/>

Eight lines. `fields` is a list of seven strings, and the three reads pick out the name, the user id and the home directory. The password field sits at position one, which is why the id is at two and not at one.

This is the Python version of `cut -d: -f1`, with a difference worth remembering: in the shell you write a new pipeline for each field, while here you split once and index the list as often as you like.

## Step 3: Join, and the way round it goes

`join` is the reverse of `split`, and it is written the way round that surprises everyone: the separator comes first.

<PyBlanks
  title="Two ways to join"
  scaffold={`parts = ["one", "two", "three"]

dashed = @1
spaced = @2

print(dashed)
print(spaced)`}
  pieces={['parts.join("-")', '" ".join(parts)', '"-".join(parts)']}
  answers={[2, 1]}
  expect={`one-two-three
one two three`}
  hint="The separator is the thing doing the joining, so it goes first, and it is a string."
/>

`"-".join(parts)` says: take this dash and use it to join this list. `parts.join("-")` is the natural guess and it fails, because a list has no such method. That is worth remembering, because it is the mistake almost everyone makes first.

The separator is a string, so `" ".join(parts)` uses a space and `"".join(parts)` glues the pieces with nothing between them.

## Step 4: f-strings, and a method that returns something new

Gluing strings with `+` gets unreadable fast and breaks when one piece is a number. An f-string puts the values inside the text.

<PyBlanks
  title="Build a line, then change it"
  scaffold={`name = "Termux"
version = 0.118

line = @1
upper = @2

print(line)
print(upper)`}
  pieces={['line.upper()', 'f"{name} {version}"', '"{name} {version}"', 'line.upper']}
  answers={[1, 0]}
  expect={`Termux 0.118
TERMUX 0.118`}
  hint="One gap needs the f. The other needs brackets, or it hands back the method instead of calling it."
/>

The `f` before the quote is the whole trick: without it the braces are literal characters. And `upper()` with brackets **returns** a new string; `line` itself is untouched, which is why the first print still shows the original.

## Step 5: Clean a field before you split it

Real data arrives with stray spaces. `strip` removes them from both ends.

<PyBlanks
  title="Clean, then split"
  scaffold={`raw = "  admin:user  "

clean = @1
left, right = @2

print(left)
print(right)`}
  pieces={['clean.split(":")', 'raw.strip()', 'raw.split(":")']}
  answers={[1, 0]}
  expect={`admin
user`}
  hint="One gap removes the spaces. The other takes the cleaned value apart."
/>

Six lines. `raw.strip()` gives `admin:user`, and then the split gives the two halves. `left, right = ...` unpacks a two-item list into two names in one go, which is the tidy way to do it.

`raw.split(":")` on the uncleaned value would give `"  admin"` with the spaces still attached, and the print would show them. That is the quiet kind of bug that only shows up in the output.

## Step 6: Loop over lines and build a list

The pattern that most scripts come down to: take a list of lines, keep one field from each, collect the results.

<PyBlanks
  title="Collect one field from each line"
  scaffold={`lines = ["root:x:0", "daemon:x:1", "bin:x:2"]

names = []
for line in lines:
    fields = @1
    @2

print(names)`}
  pieces={['names.append(fields[0])', 'line.split(":")', 'names.append(line)']}
  answers={[1, 0]}
  expect="['root', 'daemon', 'bin']"
  hint="Split the line first, then keep the first field of it."
/>

Eight lines, and this is the shape of a hundred real scripts. `names = []` starts an empty list, the loop takes each line, splits it, and appends the first field. The print at the end shows the list with its brackets and quotes, which is how Python writes a list.

`names.append(line)` would keep the whole line instead of the name, and the output would show the colons.

Turn a dotted address into a dashed one, using `split` and `join` together.

## Step 8: A mistake to find

The code runs and prints something, but it is wrong. Press Run and look at the output closely.

<PyCell
  variant="fix"
  title="Find the mistake"
  expect="admin:user"
  hint="The string inside the join is what goes between the pieces. There is nothing there."
  code={`line = "admin:user"
print("".join(line.split(":")))`}
  solution={`line = "admin:user"
print(":".join(line.split(":")))`}
/>

It prints `adminuser`, with the colon gone, because the string inside the brackets is what goes between the pieces and that string is empty. Nothing raises, so the output is the only clue.

## Quick reference

| Piece | What it does |
| --- | --- |
| `code[:3]` | the first three characters |
| `code[4:8]` | four characters starting at position four |
| `code[-4:]` | the last four characters |
| `line.split(":")` | a string into a list of fields |
| `"-".join(parts)` | a list into a string, separator first |
| `f"{name} {version}"` | values inside the text |
| `raw.strip()` | remove spaces from both ends |
| `left, right = ...` | unpack a two-item list into two names |
| `names.append(x)` | add to the end of a list |
| `line.upper()` | returns a new string, leaves the original alone |
