## Paths: absolute vs relative

An **absolute** path starts at the root, `/`. A **relative** path starts where you are now. Three
special names make relative paths powerful:

| Symbol | Meaning |
| --- | --- |
| `.` | the current directory |
| `..` | the parent directory |
| `~` | your home directory |

So `cd ..` moves up one level, `cd ~/projects` jumps home and into `projects`, and `cd -` returns
to wherever you were before.

## Listing, in more detail

```bash
ls          # names only
ls -l       # long format: permissions, owner, size, date
ls -a       # include hidden (dot) files
ls -lh      # human-readable sizes
ls -lR      # recurse into subdirectories
```

The long format is the one worth reading carefully — the first column tells you the file type and
its permissions:

```
-rw-r--r-- 1 u0_a0 u0_a0  128 Jan  1 00:00 notes.txt
drwxr-xr-x 2 u0_a0 u0_a0 4096 Jan  1 00:00 projects
```

The leading `-` means a regular file; `d` means a directory. You will read the rest of that column
in [File permissions](/learn/file-permissions/).

## Making directories

```bash
mkdir reports                 # one directory
mkdir -p projects/android/app # create the whole chain, no error if it exists
```

## Finding files

`find` walks a directory tree for you:

```bash
find . -name "*.log"       # every .log file below here
find . -name flag.txt      # hunt for a specific name
find / -type f -name "*.conf" 2>/dev/null   # system-wide, hiding permission errors
```

`2>/dev/null` discards error messages — we cover redirection properly in
[Pipes and redirection](/learn/pipes-and-redirection/).

## Seeing the shape of a tree

```bash
tree            # a visual tree of the current directory
tree -L 2       # only two levels deep
```
