Service detection performed. Please report any incorrect results at https://nmap.org/submit/ .
Nmap done: 1 IP address (1 host up) scanned in 6.77 seconds
```

The table now has a `VERSION` column, and the row is worth reading in full. `8010/tcp` is the port. `open` is the state. `http` is the service, and `SimpleHTTPServer 0.6 (Python 3.12.13)` is the version string `nmap` worked out from what the server said. The line `Service detection performed` confirms the probe ran. That version string is the point of the whole command: it is the thing a known issue attaches to.

`-sV` is a best effort, not a promise. Some services say nothing useful, and `nmap` will then print a question mark or leave the column blank. When that happens, the next step is to read the banner by hand.

## Step 3: Read the banner by hand

A service often announces itself in the first line or two it sends. `curl` with `-I` asks for the response headers only, which is where a web server puts its version.

```bash
curl -sI http://127.0.0.1:8010/
```

```text
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.12.13
Date: Sun, 25 Oct 2026 04:36:18 GMT
Content-type: text/html; charset=utf-8
Content-Length: 263
```

The `Server` line is the banner, and it matches what `nmap` reported. The `-s` flag silences the progress meter and `-I` asks for headers rather than the body, so the output is short and easy to read. Not every service announces a version, and some announce a false one on purpose. Treat a banner as evidence, not as proof, and confirm it another way when it matters.
