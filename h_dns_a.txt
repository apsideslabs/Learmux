Every time you open a site, your phone has to turn a name into an address before it can send anything. That translation is DNS. In this lesson you will find the resolver your phone uses, ask it for several kinds of record, and read the replies yourself. By the end you will know what happens between typing a name and reaching a server.

## What you'll be able to do

- Find the DNS resolver your phone is using.
- Ask for A, AAAA, MX and TXT records with dig and nslookup.
- Read the answer section of a dig reply.
- Tell the difference between a name and an address.
- Follow a CNAME and run a reverse lookup.

## Step 1: Find your resolver

A resolver is the server your phone asks when it needs to turn a name into an address. On Android it is stored as a system property. The getprop command reads those properties, and it is available in Termux.

Read the first resolver address:

```
getprop net.dns1
```

```
192.168.1.1
```

That address is your router, which forwards the question on. Some phones leave this property empty and fill in the second one instead. To see every DNS property at once, filter the full list:

```
getprop | grep -i dns
```

```
[net.dns1]: [192.168.1.1]
[net.dns2]: [8.8.8.8]
```

The first entry is your local resolver, and the second is a fallback.

<Callout type="tip" title="The resolver is a choice">
The address you see here decides who answers your questions. Changing it later is a real change to how your phone works.
</Callout>

## Step 2: Ask for an address

dig is the standard tool for asking DNS questions. It ships in the dnsutils package, which you may need to install first.

```
pkg install dnsutils
```

```
Reading package lists... Done
Setting up dnsutils (9.18.28) ...
```

Now ask for the address of example.com. The A record type holds an IPv4 address:

```
dig example.com A
```
